# Мини-библиотека

Небольшое клиент-серверное приложение для лабораторной работы по CI/CD. Сервер написан на FastAPI, данные хранятся в SQLite, а браузерная страница позволяет работать с записями без отдельного фронтенд-проекта. Docker не используется.

## Что реализовано

Пять сущностей: авторы, жанры, книги, читатели и выдачи. Для каждой есть пять HTTP-операций: получение списка, получение одной записи, создание, изменение и удаление. Это 25 API-операций, включая все четыре действия CRUD для каждой из пяти сущностей.

| Сущность | Путь API | Связи |
| --- | --- | --- |
| Авторы | `/api/authors` | — |
| Жанры | `/api/genres` | — |
| Книги | `/api/books` | автор и жанр |
| Читатели | `/api/readers` | — |
| Выдачи | `/api/loans` | книга и читатель |

База создаётся автоматически при запуске приложения. Файл `library.db` специально исключён из Git: личные данные и изменения базы не должны попадать в коммиты и не должны затираться при развертывании. Удалить автора, жанр, книгу или читателя со связанными записями нельзя — API вернёт код 409.

## Первый запуск на Windows

Нужен Python 3.10 или новее. В PowerShell, находясь в папке проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn library.main:app --host 127.0.0.1 --port 8000
```

Затем откройте `http://127.0.0.1:8000` — простая страница приложения. Интерактивная документация API доступна по адресу `http://127.0.0.1:8000/docs`. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

Если PowerShell не находит `py`, используйте установленную команду `python`. Для учебного локального запуска сервер слушает только `127.0.0.1`, а не весь интернет.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты используют отдельную временную SQLite-базу и не меняют ваши демонстрационные данные. Они покрывают CRUD всех пяти сущностей, ошибки связей и наличие 25 операций в API.

## Ветки для лабораторной

`main` — стабильная версия для развертывания. `develop` — подготовка изменений. `feature/demo-banner` — пример ветки с новым видимым изменением на главной странице. Изменения в `develop` и `feature/demo-banner` не должны автоматически попадать на развернутый сайт. После слияния в `main` и push туда Jenkins сможет выполнить тесты и доставить новую версию.

## Что остаётся сделать вручную для CI/CD

Jenkins, GitHub webhook и CD в этом репозитории **ещё не настроены** — это отдельная часть лабораторной. При настройке Jenkins важно держать его рабочую папку и папку работающего сайта раздельно. Для Windows Jenkins Pipeline использует шаг `bat`, выполняет `python -m pytest` на всех ветках и развертывает только `main` после успешных тестов. GitHub webhook должен отправлять событие `push` на доступный Jenkins URL. Не копируйте `library.db` поверх рабочей базы при каждом deploy.

Для демонстрации: откройте работающий сайт из папки развертывания, измените баннер в feature-ветке, сделайте commit — сайт прежний; сделайте push в feature-ветку — сайт прежний; слейте изменение в `main` и сделайте push — после успешного Jenkins deploy сайт обновится.

## Структура

```text
library/
  database.py       создание таблиц и соединение с SQLite
  main.py           API-маршруты и обработка CRUD
  static/           простая HTML/CSS/JS-страница
tests/
  test_crud.py      автоматические проверки
requirements.txt   Python-зависимости
```
